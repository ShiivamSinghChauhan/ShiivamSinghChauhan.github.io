Self-Healing RAG Featured

09/2026

Problem: normal RAG answers confidently even when the retrieved text doesn't support the answer.

  • Built a document Q&A system that checks its own answers: a critic verifies each answer against the retrieved text.
  • If an answer isn't supported, the system rewrites the query and retries in a LangGraph loop, instead of returning a guess.
  • Combined ChromaDB vector search with BM25 keyword search, then a cross-encoder reranker to keep the best chunks.

LLM Guardrails Gateway

07/2026

Problem: apps that send user text straight to an LLM are open to prompt injection, jailbreaks and personal-data leaks.

  • Built a FastAPI gateway that sits in front of the LLM: it blocks prompt injection, jailbreaks and PII, and flags policy violations in outputs.
  • Added Meta's Prompt-Guard-2 classifier on top of regex rules, raising attack recall while keeping false positives low.
  • Used Redis for per-key rate limiting and for caching guard decisions, so repeated prompts skip the classifier.
  • Policies are YAML files editable at runtime, with audit logging and a /metrics endpoint for block rate and p50/p99 latency.

Agentic RAG Chatbot

06/2026

Problem: a chatbot that only knows its training data can't answer from your PDFs or live information.

  • Built a chatbot with streaming replies and saved chat threads using LangGraph's PostgreSQL checkpointer.
  • Turned it into a tool-calling agent that chooses between web search, APIs and uploaded PDFs indexed in FAISS.
  • Used LangSmith traces to debug the agent's tool choices, and measured answer quality with RAGAS.

Customer Feedback Classifier

12/2025

Problem: LLM output is unreliable for software — one malformed JSON breaks the pipeline.

  • Classifies customer feedback into a typed Pydantic schema: sentiment, 8 categories, urgency, bounded confidence, summary and action items.
  • Built a self-correcting loop in LangGraph: when the parser rejects the LLM's output, the validation error is sent back and the model repairs its own JSON.
  • A second LCEL chain turns stored results into a validated insights report — risks, wins, trends and actions — served through FastAPI and a Streamlit dashboard.
How it works
1Feedback text comes in
2LCEL chain with few-shot prompt
3Pydantic parser validates the JSON
↺Invalid → error sent back, model fixes its output
4Saved to SQLite → dashboard + insights report

How I work

Three habits in every project

Measure, don't guess

I write a test set first and report real numbers — accuracy, recall, false positives — instead of "it looks good".

Make it observable

Traces for every step (LangSmith), audit logs and latency metrics, so I can see exactly where a system fails.

Plan for failure

Self-checks, retries, validation and guardrails, so a bad model output is caught before a user sees it.
